# Musea 商业需求文档 (Business PRD)

> **版本**: v1.0
> **日期**: 2026-05-17
> **状态**: 草案

---

## Problem Statement

Unsplash 拥有全球最大的免费高质量图片库之一，但其官方客户端和 Web 体验在图片**发现**方面较为基础：

- 浏览体验以列表为主，缺乏沉浸式的视觉探索流程
- 图片发现路径单一（搜索+编辑推荐），缺少基于颜色、内容关联的浏览方式
- 移动端体验不完整，缺乏原生的跨平台应用
- 元数据展示不够突出，照片背后的相机参数、地理位置、颜色信息没有很好的呈现

Musea 旨在打造一个**以发现为核心**的图片浏览应用，让普通用户能够以更直观、更优雅的方式探索海量高质量摄影作品。

---

## 项目性质

> **本项目为个人学习项目**，不追求商业指标和用户数据。通过在真实 API 上构建完整应用来实践 Flutter 跨平台开发能力。

但这不代表产品质量可以打折扣——作为个人作品集项目，Musea 仍应追求优质的用户体验和代码质量。

## Target Users

| 用户类型 | 特点 | 需求 |
|---------|------|------|
| **普通内容消费者** | 喜欢浏览美图、寻找壁纸、日常视觉灵感 | 轻松浏览高质量图片，发现感兴趣的内容 |
| **摄影爱好者** | 关注摄影作品，关心相机参数和摄影技巧 | 查看 EXIF 信息，关注摄影师，学习摄影 |
| **设计师/创意工作者** | 需要视觉参考和美学灵感 | 按颜色/主题筛选图片，建立参考收藏 |
| **个人开发者** | 学习 Flutter 和调用 REST API 的技术实践者 | 关注项目架构、API 集成、最佳实践 |

MVP 阶段主要服务**普通内容消费者**和**摄影爱好者**。

---

## Solution Overview

**Musea** 是一个基于 Flutter 构建的跨平台图片发现应用，通过 Unsplash API 提供以下核心体验：

- **沉浸式浏览** — 瀑布流或网格布局浏览最新/精选图片，更具视觉冲击力
- **智能搜索** — 支持关键词、颜色、方向等多维度搜索过滤
- **丰富详情页** — 展示完整图片元数据，包括 EXIF、位置、颜色信息、标签
- **收藏集管理** — 用户创建主题收藏集，分类保存喜爱的图片
- **摄影师探索** — 查看摄影师主页及其作品集

通过精心设计的 UI/UX，将原本简单的 API 数据转化为流畅、美观的视觉浏览体验。

## Unsplash API 数据接口分析

### 可用端点总览

| 类别 | 端点 | 用途 | MVP 优先级 |
|------|------|------|-----------|
| **照片** | `GET /photos` | 获取编辑推荐照片列表 | ★★★ |
| **照片** | `GET /photos/:id` | 获取单张照片完整详情（EXIF、位置、标签） | ★★★ |
| **照片** | `GET /photos/random` | 获取随机照片（可限定集合/主题/方向） | ★★★ |
| **照片** | `GET /photos/:id/statistics` | 获取照片浏览/下载统计数据 | ★★☆ |
| **照片** | `GET /photos/:id/download` | 跟踪下载行为（API 合规要求） | ★★★ |
| **搜索** | `GET /search/photos` | 关键词搜索照片，支持颜色/方向/排序过滤 | ★★★ |
| **搜索** | `GET /search/collections` | 搜索收藏集 | ★★☆ |
| **主题** | `GET /topics` | 获取 Unsplash 官方策划主题 | ★★★ |
| **主题** | `GET /topics/:id/photos` | 获取主题下的照片 | ★★★ |
| **用户** | `GET /users/:username` | 获取摄影师公开资料 | ★★☆ |
| **用户** | `GET /users/:username/photos` | 获取摄影师作品列表 | ★★☆ |
| **收藏集** | `GET /collections` | 获取收藏集列表 | ★☆☆ |
| **收藏集** | `GET /collections/:id/photos` | 获取收藏集中的照片 | ★☆☆ |
| **收藏集** | `POST /collections/:id/add` | 添加照片到收藏集 | ★☆☆ |
| **收藏集** | `DELETE /collections/:id/remove` | 从收藏集移除照片 | ★☆☆ |

### 数据模型关键字段

**Photo 对象**：
- `id`, `created_at`, `width`, `height`, `color`（主色调 HEX）, `blur_hash`（模糊占位）
- `description`, `alt_description`, `tags`（标签数组）
- `urls`: `raw`/`full`/`regular`/`small`/`thumb`（五种尺寸）
- `exif`: `make`/`model`/`exposure_time`/`aperture`/`focal_length`/`iso`
- `location`: `city`/`country`/`position.lat`/`position.lng`
- `user`: 摄影师资料（含 `name`/`username`/`profile_image`/`portfolio_url`/`bio`）
- `links`: `download`/`download_location`（下载追踪）
- `likes` 计数

**图片 URL 处理**（Imgix）：
- 五种预定义尺寸（raw/full/regular/small/thumb）
- 支持实时参数：`w`(宽)、`h`(高)、`q`(质量)、`fm`(格式)、`fit`(适配)、`dpr`(像素比)
- **必须保留 `ixid` 参数**以符合 API 使用规范

### 认证策略

| 阶段 | 认证方式 | 可用功能 | 速率限制 |
|------|---------|---------|---------|
| MVP | `Client-ID` 公开认证 | 浏览/搜索/详情/主题（只读操作） | 50次/小时（演示）→ 可申请生产提升 |
| 后续 | `OAuth 2.0` 用户认证 | 收藏集管理/点赞/用户数据（读写操作） | 5000次/小时（生产） |

### 数据使用合规要点

1. **下载追踪**：每次用户下载图片必须调用 `/photos/:id/download` 端点
2. **热链接**：直接使用 Unsplash CDN 图片 URL（`images.unsplash.com`），不计入 API 限额
3. **署名**：展示图片时必须显示摄影师署名
4. **ixid 保留**：图片 URL 中的 `ixid` 参数不可移除

## User Stories

### 第一阶段 — 浏览与发现

1. 作为普通用户，我希望打开应用就能看到精选/最新的高质量图片，以便快速浏览发现好照片
2. 作为普通用户，我希望以瀑布流/网格布局浏览图片，获得比官方更流畅的视觉体验
3. 作为普通用户，我希望按主题（如"自然"、"建筑"、"人物"）浏览图片，以便发现特定类别的作品
4. 作为普通用户，我希望可以刷新获取新的推荐内容
5. 作为普通用户，我希望看到随机推荐的照片，获得意外发现的惊喜感
6. 作为普通用户，我希望在浏览列表中使用图片的 BlurHash 作为加载占位，减少等待焦虑

### 第二阶段 — 搜索

7. 作为普通用户，我希望能通过关键词搜索照片，以便找到感兴趣的特定内容
8. 作为普通用户，我希望能按颜色过滤搜索结果，以便找到与特定色调整体搭配的图片
9. 作为普通用户，我希望能按方向（横向/纵向/方形）过滤搜索结果，以适配不同使用场景
10. 作为普通用户，我希望能按相关度或最新排序搜索结果
11. 作为普通用户，我希望搜索结果有良好的加载和空状态处理

### 第三阶段 — 图片详情

12. 作为普通用户，我希望能点击图片进入详情页，查看大图
13. 作为摄影爱好者，我希望查看照片的 EXIF 信息（相机型号、光圈、快门速度、ISO、焦距）
14. 作为摄影爱好者，我希望查看照片的拍摄位置（城市/国家/经纬度）
15. 作为普通用户，我希望查看图片的主色调和配色信息
16. 作为普通用户，我希望查看图片的标签，并通过标签跳转到相关图片搜索
17. 作为普通用户，我希望查看摄影师信息（姓名、个人简介、作品数量），并跳转到摄影师主页
18. 作为普通用户，我希望能够下载不同尺寸的图片
19. 作为普通用户，我希望在详情页看到推荐的相关/相似图片
20. 作为普通用户，我希望在详情页看到图片的统计数据（下载量、浏览量）

### 第四阶段 — 收藏集

21. 作为普通用户，我希望能创建自己的收藏集（如"旅行灵感"、"壁纸"）
22. 作为普通用户，我希望能将喜欢的图片添加到收藏集中
23. 作为普通用户，我希望能浏览自己收藏集中的图片
24. 作为普通用户，我希望能从收藏集中移除图片
25. 作为普通用户，我希望能编辑收藏集的名称和描述
26. 作为普通用户，我希望能查看 Unsplash 平台上的公开精选收藏集

### 第五阶段 — 摄影师探索

27. 作为普通用户，我希望能查看摄影师的个人资料页（简介、作品数量、社交链接）
28. 作为摄影爱好者，我希望能浏览摄影师的全部作品
29. 作为摄影爱好者，我希望能查看摄影师的统计数据

### 第六阶段 — 错误与边界处理

30. 作为用户，当网络不可用时，我希望看到友好的离线状态提示
31. 作为用户，当 API 达到速率限制时，我希望得到清晰提示
32. 作为用户，当搜索结果为空时，我希望看到友好的空状态引导
33. 作为用户，当图片加载失败时，我希望看到降级显示而不是白屏
34. 作为用户，我希望下拉刷新在失败时也有明确反馈

## 技术依赖与约束

### 已知依赖

| 依赖项 | 说明 | 备注 |
|-------|------|------|
| Unsplash API | 所有图片数据来源 | 需注册开发者账号获取 Client-ID |
| Flutter SDK | 跨平台开发框架 | 版本待定 |
| Unsplash API 速率限制 | Demo: 50次/h, Production: 5000次/h | MVP 阶段需申请 Production 级别 |
| Imgix CDN | 图片加载和渲染 | URL 参数需保留 ixid |

### 约束

- 遵守 Unsplash API Guidelines（下载追踪、署名、ixid 保留）
- 移动端为主，暂不考虑桌面端适配
- 图片数据全部依赖 Unsplash，无法离线使用

## Risks & Mitigations

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| API 速率限制不足 | 高 | 用户体验受限 | 申请 Production 级别（5000/h）；实现本地缓存减少请求 |
| 依赖单一数据源 | 中 | 服务不可用时应用瘫痪 | 实现优雅的错误处理和降级显示 |
| 图片加载性能 | 中 | 列表卡顿、流量消耗大 | 使用 BlurHash 占位、按需加载不同尺寸、缓存策略 |
| Flutter 学习曲线 | 中 | 开发进度慢 | 合理规划时间，先搭建骨架再细化 |
| API 变更 | 低 | 部分功能不可用 | 关注 Unsplash Changelog，预留适配层 |

## Out of Scope

以下功能明确不在当前规划内：

- **用户注册/登录系统** — 收藏集数据使用本地存储（SharedPreferences / SQLite）
- **社交功能** — 无点赞、评论、关注
- **图片上传** — Musea 是发现工具，不是摄影社区
- **Web/桌面端** — 聚焦移动端体验
- **多语言支持** — MVP 仅支持中文或英文单语言
- **无障碍适配** — 非核心需求
- **离线缓存图片** — 仅缓存元数据，不缓存原图
- **推送通知** — 无需要推送的场景

## Open Questions

1. **设计风格**: 视觉风格尚未确定——极简留白、沉浸暗色、还是杂志卡片风格？需在开发前完成设计探索
2. **Flutter 状态管理方案**: BLoC vs Riverpod vs Provider？需在开发前确定
3. **本地存储方案**: SharedPreferences vs Hive vs SQLite (drift) 用于收藏集本地存储？
4. **图片缓存策略**: 使用 cached_network_image 还是自建缓存层？
5. **地图展示**: 位置信息是否需要用地图展示，还是仅文本显示？是否引入 google_maps_flutter 或 Mapbox？
